## Server changes still needed

Do not invent these on the phone. The live server does not have them.

1. **Memory, so You can view and manage it**

   ```http
   GET /api/client/memory
   Authorization: Bearer <device token>
   ```

   ```json
   { "ok": true, "items": [{ "id": "…", "text": "…", "kind": "fact", "updated_at": 0 }] }
   ```

   ```http
   POST /api/client/memory
   { "text": "correction or note" }
   ```

   ```http
   POST /api/client/memory/forget
   { "id": "…" }
   ```

   Until those exist, the phone can only show Observation it has queued, not what home has stored.

2. **Approvals when the app is not open**

   There is no push or event stream. Polling `GET /api/client/approvals` works only while the process is running. To notify in the background:

   ```http
   POST /api/client/push/register
   { "expo_push_token": "…", "platform": "android" }
   ```

   The push body must be an opaque approval id, not Memory or Chat text. An alternative is `GET /api/client/events` as server-sent events.

3. **Home app status and Away URLs**, if they are not already fields on `GET /api/client/home-openers`

   Each app should include `status` (`up` or `down`), `lan_url`, and `https_url` (or `away_url`) when that app is published off the LAN. The client API host `https://atleyos.atley.llc` is not the Immich or Nextcloud URL. This phone will not point Photos or Files at it.

4. **Confirm these bodies** (the phone will send them; a 400 should name the field the server expects):

   - `POST /api/client/approvals/decide` `{ "id": "<id>", "decision": "allow" | "deny" }`
   - `POST /api/client/approvals/<id>/decide` `{ "decision": "allow" | "deny" }` if the id is in the path
   - `POST /api/client/favorites/toggle` `{ "id": "<id>", "entity_id": "<entity>" }`
   - `POST /v1/chat/completions` with `"stream": true` as OpenAI SSE (`data: {"choices":[{"delta":{"content":"…"}}]}` then `data: [DONE]`). `"model": "atleyos"` stays the router alias so the active conversation model on the server is the one that answers.
   - `GET /api/client/conversations` items should include `id`, `title`, and `messages: [{ "role", "content" }]`, or `GET /api/client/conversations/<id>` should.
