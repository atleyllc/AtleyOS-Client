## Contract now matched

Server PRs #14 (memory), #15 (approval push opt-in and SSE), and #16 (home status, streaming chat, conversations) are the contract in the attached `docs/client-api.md` summary. This phone follows that summary. Older servers that still 404 or 405 those routes keep the previous empty states. The private repo `atleyllc/AtleyOS` was still not readable from this environment, so the summary is the source of truth.

- Memory kinds are `relationship`, `preference`, `correction`, `decision`, `pattern`, `context`. The phone does not send `kind` or `fact`. `{text}` is what home stores as `context`. Errors: `empty_text`, `text_too_long`, `invalid_kind`, `missing_id`, `owner_required`, `not_found`.
- Favorites read `id`, `entry_id`, `entity_id`, `label`, `domain`, `state`. Toggle still sends `{id, entity_id}` when both exist.
- Home rows use `status`, `lan_url`, and `https_url`. StrikeNote and Anchor appear only when the server lists them.
- Chat posts `model: "atleyos"` and `stream: true`. `conversation_id` on a chunk is stored on the local thread.

### Remaining mismatch

The summary names the Owner switch **Approval push** (Remote Access, default off) and says registering a token does not turn it on. It does not name the JSON field on `GET /api/client/status`.

Until that field is named, this phone treats the switch as on only when status, `remote_access`, `remote_access.settings`, or `device` includes a boolean — or `{enabled: boolean}` — under one of these keys:

- `approval_push`
- `approval_push_enabled`
- `push_approvals`
- `approvals_push`

If none of those keys is present, the phone does **not** call `POST /api/client/push/register`. SSE still runs. A push payload is handled as `data: {id}` only; the title and summary are loaded from `GET /api/client/approvals`.
